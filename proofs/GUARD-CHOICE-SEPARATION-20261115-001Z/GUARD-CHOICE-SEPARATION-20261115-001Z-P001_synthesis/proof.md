# When switch settings let two blocks forget a shared choice

Status: Proved

## Accepted conclusions

- Splitting one shared Boolean choice preserves a boundary triple exactly when an empty local support excludes the split triple or the two supports intersect. Complete witnesses can be reconstructed with separate searches over the internally mixed-sign pads. [A, candidate-local-delta](../../GUARD-CHOICE-SEPARATION-20261115-001A/GUARD-CHOICE-SEPARATION-20261115-001A-P001_boundary_supports/proof.md)
- On one fixed two-stage raw formula, changing a single guard can make a shared middle essential to satisfiability. Across a complete-stage cut sharing only padding names, every boundary triple is preserved for any number of those names and any switch settings. [B, candidate-local-delta](../../GUARD-CHOICE-SEPARATION-20261115-001B/GUARD-CHOICE-SEPARATION-20261115-001B-P001_live_switches/proof.md)
- Recognizing a safe split of one middle is NP-hard on two-use schedules fixed per source width, both for all observed triples and for the outer pair after the cut bit is hidden. General triple equality in this one-middle setting can be tested with four nonadaptive SAT queries. [C, candidate-local-delta](../../GUARD-CHOICE-SEPARATION-20261115-001C/GUARD-CHOICE-SEPARATION-20261115-001C-P001_recognition_cost/proof.md)
