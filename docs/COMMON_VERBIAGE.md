# Common Verbiage

These are guarded working definitions. A proof artifact may strengthen them
inside a frozen model, but may not weaken their required contact-first gates.

| Term | Working definition |
| --- | --- |
| Substrate | The declared objects, states, native laws, observations, restrictions, transports, and recodings available to a model. |
| Native formation | Construction by the substrate's declared objects and native operations, with the required witness internally available. It is stronger than describing, encoding, or recognizing an object. |
| Faithful external presentation | An analyst-facing structure that preserves a declared native object or relation without claiming to originate it. |
| Solution-only encoding | A representation preserving selected solutions or answers while making no claim to preserve native formation, intervention, recurrence, or contact structure. |
| Serialization | A finite record of an already specified object or witness. The ability to serialize a knot does not give the record-producing language a native knot mechanism. |
| Native continuation | A substrate operation or relation specifying which logical role or compatible state follows another. It is not physical time or motion unless separately constructed. |
| Recurrence witness | The substrate-native data and law showing that a continuation closes and can continue again. A host loop, drawing, or observer's periodic record is not such a witness. |
| Native recurrence | A nontrivial closed continuation structure that returns to the same logical role with the compatibility required to continue again. A drawn cycle or syntactic cycle is only a candidate. |
| Independent recurrences | Two native recurrences separately witnessed so that neither is merely a renamed, duplicated, or observer-partitioned presentation of the other. |
| Recurrence/topology mnemonic | “A recurrence is an atom of persistence; a complete logical knot is an atom of intrinsic relation” is explanatory shorthand only. A recurrence closes under its own native continuation and supplies no relative existence by itself. In a complete knot, the contact qua contact—not the independent recurrence witnesses—is jointly dependent on both recurrence roles and is lost when either role is erased. This does not weaken any contact gate. |
| Shared identity | The claim that both recurrences use one and the same substrate object or interface, not two objects with equal labels, values, or behavior. |
| Touch / touch point | Informal language for shared contact. It names identity-level common participation, not a point or meeting location in prior space. |
| Irreducible joint contact | One native relation involving both distinct recurrence roles and their one contact object such that the relation cannot be replaced by independent `A-k` and `B-k` attachments while preserving contact. Erasing either recurrence destroys the contact qua contact. |
| Common hub | A shared object `k` attached independently to `A` and `B`. Shared identity may hold, but this decomposable structure is not the one irreducibly joint touch between the loops. |
| Persistent contact | One identity-shared, irreducibly joint object/interface relation that participates in both recurrence laws and remains identifiable under every admitted recurrence, restriction, transport, and recoding. |
| Contact intervention | A source-bound typed native action used to probe an already formed contact or topology witness. In Proof 0052, disable and split actions carry an exact source, a typed `InterventionState` target, a native domain, and primitive support exactly equal to their writes; role erasure is separately role-local. An intervention may destroy a witness but does not originate one. |
| Primitive action support / observation dependency support | Primitive action support is the exact finite family of native fields an action writes. Observation dependency support is the exact family read by one native evaluator. They are distinct: a one-field local action may change a composite observation whose dependency support contains that field. |
| Native finite first variation | Proof 0052's record \((O(S),O(T),\mathsf{Changed}\mid\mathsf{Unchanged})\) for one formed source-bound action \(S\to T\), carrying the corresponding native inequality or equality witness. It is not subtraction, magnitude, a derivative, or a gradient. |
| Native mixed-variation square | Proof 0052's four-corner record for two same-source actions, including both terminal orders. Disjoint primitive supports commute only when both residual-action domains remain stable; overlap may form an explicit undefined-square obstruction. It is an action theorem, not a numeric second difference or second derivative. |
| Retained-support restriction / support-erasure obstruction | A Proof 0052 action commutes with native restriction only when its support, domain, and required source records survive. If restriction erases the support, no restricted action is formed; the result is an obstruction, never an inert variation. |
| Guarded logical-unknotting action contract | Proof 0054's frozen finite typed elementary-action alphabet with exact source, codomain, effect, positive native finite cost, recurrence/identity/contact preservation requirements, intermediate admissibility, and a declared target-predicate type. It is the contract needed before minimizing action costs; it is not itself an unknotting number. |
| Empty-sequence zero / `NoAdmittedSequence` | Empty-sequence cost zero is formed only when the declared target already holds at the source. `NoAdmittedSequence` is a complete finite certificate that none of the frozen admitted sequences reaches that target. The latter is not a numeric or rational infinity. |
| Two-sided essentiality | A paired intervention result: splitting, deleting, disabling, or independently varying the contact changes a declared native consequence of each recurrence separately. |
| First emergence | Formation of one persistent, identity-shared, two-sided-essential, irreducibly joint contact between two independently witnessed native recurrences, with contact lost when either recurrence is erased. This first intrinsic relational event is also the first atomic logical topology. |
| Logical knot | The complete package of the two recurrences, their persistent irreducibly joint essential contact, loop-erasure contact loss, and native coupling laws. The term is project-specific and does not assert a classical knot or link. Since 2026-10-19 the contact conditions are decided on allowed states by the knot test K1–K3; whether the loops are native recurrences is decided separately. |
| Knot test (K1–K3) | The canonical test, adopted on 2026-10-19, for a relation over the open distinctions of loops and one contact variable. Erasing a loop forgets it. K1 binding: the relation is constrained as a whole. K2 loss on erasure: forgetting any one variable, a loop or the contact, leaves the rest unconstrained. K3 coexistence: some state is allowed. In short, constrained as a whole and unconstrained in every part. Witnesses are quantified away, no executor supplies an input, and the verdict depends only on the allowed states. For two loops 34 relations pass, in five shapes from the atom `¬A ∨ ¬B ∨ c` to parity. No 2-CNF with witnesses passes. Three-literal clauses with named intermediates define every knot (`KNOT-FOUNDATION-20261019-001E-P001`). An earlier reading treated erasure as setting a presence variable to absent; it keeps only the atom (`KNOT-FOUNDATION-20261019-001A-P001`). Check with `tools/knotlab`. |
| Native knot-emergence rate | A guarded structural scaling profile for complete logical knots in registered, source-bound finite instances. Its primary datum is a certificate-independent atomic-knot census, and at a fixed external syntax budget `(V,C,L,H,N)` it is generally an attainable spectrum rather than a byte-extensional function, because native formation authority is not determined by formula bytes. Ratios or all-size laws require explicit presentation controls and proof. The term does not mean XOR count, graph incidence, witness multiplicity, transcript effort, runtime, minimal contact-distance magnitude, or a complexity-class result. |
| Emergence--complexity nonidentification theorem | The proved `JOINTNESS-COMPLEXITY-001Z-P001` result that native emergence authority and computational resource complexity are different typed properties at the declared interface. Native emergence is a source-bound formation judgment requiring retained complete-contact evidence; computational complexity quantifies resources for a frozen byte-extensional task and machine or proof model. A byte-identical registered/bare counterpair prevents ordinary byte-extensional tasks or resource functions from reflecting native authority, while read-twice and direct-scan controls show that a restricted-model lower bound is not an intrinsic emergence magnitude. The theorem does not forbid a future separately proved task-essential bridge and proves neither `P != NP` nor `P = NP`. |
| Entwined | A guarded informal description of two recurrences coupled through a proved shared contact. It does not mean linked, crossed, wound, or embedded in ambient space. |
| Atomic logical topology | The first nontrivial spatial structure: one complete logical knot in which each of two distinct native recurrences exists intrinsically relative to the other through their one genuine contact. It is premetric and does not presuppose an ambient topological space. |
| Loop-relative position | Information carried by proved contact: from the native context of one recurrence, another distinct recurrence exists relative to it through the same contact. For multiple loops, a relational profile records the complete contacts and native composition roles involving that loop. This is not an observer viewpoint or coordinate. |
| Indirect loop-relative position | Relative presence established by a proved native path through one or more intermediate recurrences and complete contacts. It does not create direct endpoint contact, a coordinate, numerical length, connectivity theorem, separation, or metric. |
| Logical topology | The contact-first family of intrinsic relative structures. It begins atomically with one complete logical knot and extends compositionally through coherent networks of complete contacts. It is not raw incidence, a quotient, a parity field, or automatically a classical topology. |
| Composed logical topology | A coherent same-substrate organization of at least two complete contacts under proved composition, restriction, transport, and recoding laws. It is downstream of atomic logical topology and upstream of native routes, reachability, separation, and possible metric enrichment. |
| Contact network | Complete contacts that coexist in one declared native substrate, preserve compatible endpoint identities without collapse, and compose by substrate-native laws persistent under admitted restrictions, transports, and recodings. A finite carrier may contain several disconnected qualified pieces, but their coexistence supplies no cross-piece route or connectedness. A larger common hub, observer-drawn graph, or externally imposed composition does not qualify. |
| Minimal contact-distance | The primitive qualitative or premetric distinction-in-relation realized only after the complete contact gate: two native recurrences, shared identity, two-sided essentiality, irreducible jointness, loop-erasure contact loss, and persistence. Then `A` remains `A`, `B` remains `B`, `A != B`, and the genuine touch relates them without collapse. It is one indivisible contact unit—the smallest available qualitative measure of relative existence—but has no independently supplied magnitude, direction, coordinate, path length, or metric axioms. |
| Intrinsic adjacency | The operational relation carried by the same genuine touch that realizes minimal contact-distance. Proof 0009 first forms this complete witness; Proof 0006 retains only a pre-jointness proxy-relation theorem. It is not an analyst-inserted edge or neighborhood. |
| Path | A substrate-native composition of proved minimal contact-distances/intrinsic adjacencies within a proved composed logical topology. A path in an analyst-supplied graph is not automatically native. |
| Native route | A typed substrate-formed carrier with source and target identities. An identity route contains no contact, an oriented direct route contains one complete contact, and a multi-contact route contains a native successor trace. Endpoint-matched concatenation is partial. Route orientation is distinct from bilateral atomic contact. |
| Directed reachability | `A` natively reaches `B` exactly when the declared substrate forms an admitted native route from `A` to `B` and internally closes the relevant route relation. Identity routes support reflexivity and native concatenation supports the transitivity available in a composition-complete carrier. Host graph closure has no formation authority. |
| Mutual-reachability component | An identity-preserving membership class formed when native reachability holds in both directions. Members remain distinct recurrence identities; the component is not automatically an external quotient or weakly connected component. |
| Native disconnection | A relation certified by a completed native route relation containing neither orientation between the selected identities or components. A missing drawn edge or failed search is insufficient. |
| Native separation | A declared role/contact intervention that meets every admitted native route state between selected recurrence sets, together with pre-intervention reachability and an internally completed post-intervention route relation proving absence. It is relational and nonnumeric. |
| Separation | Use `native separation` for the proved intervention-and-complete-route-absence structure. Broader topological, geometric, or quantitative separation notions require separate definitions and proofs. |
| Relative-information profile | A typed record of the contact, route-orientation, reachability, component, disconnection, intervention, or separator information available relative to one recurrence. The selected fields and their authority must be explicit; equal profiles need not determine equal native carriers. |
| Faithful relational signature | The smallest explicitly typed field family proved sufficient, within a declared carrier contract, to preserve and reflect that carrier up to admitted recoding. In the current finite contract it retains recurrence records, bilateral contact incidence, orientation, route successors, native operations, and composition completeness. It remains a faithful external presentation. |
| Faithful relational reconstruction | Preservation and reflection of a declared native carrier, up to admitted recoding, from an explicitly typed relational signature. Exact reconstruction of a presentation does not make the signature the native formation mechanism. |
| Derived neighborhood | A loop-relative family computed from proved contact, route, reachability, component, or intervention data. Its exact relation and authority must be named. A derived neighborhood does not originate adjacency or atomic topology. |
| Derived finite topology | A finite open-set structure proved from a selected loop-relative preorder or equivalence neighborhood. It is a faithful derived classical topology, not the first atomic logical topology, not composed logical topology, and not a native cut operation. |
| Finite native restriction | The carrier produced by a declared finite role-erasure or contact-disable intervention. Relative profiles and derived topology are recomputed on the target carrier; they are not generally obtained by intersecting the source presentation. |
| Combinatorial space | A nonmetric derived structure built only after the relevant native carrier or faithful relational signature supports proved neighborhood, finite-topology, separation, invariant, or refinement operations. Counts, ranks, coordinates, metrics, and continua remain separate constructions. |
| Contact-native logical program | A typed source or target object with declared input, initialization, internally represented state, native execution semantics, termination or productivity behavior, and typed output. Program formation and execution do not by themselves form a logical knot; every emergence claim still requires the complete contact gate in the target substrate. |
| Proof-carrying logical computation toolchain | The planned umbrella containing a target-language runner, independent trace and contact checker, source-to-target compiler, and their exact correspondence contracts. The parts have separate authority: execution can be studied without a compiler, while compilation correctness is stated only relative to the frozen runner semantics and checker. |
| Proof-carrying logical program runner | A planned executor for one frozen target language that loads typed input, preserves declared state identities, applies only registered native transition rules, returns typed output or a declared nonterminal outcome, and emits a trace for an independent checker. Running or accepting a target does not originate emergence. |
| Proof-carrying logical emergence compiler | A guarded name for a source-to-target translation that emits checkable lowering, program, and contact certificates and is proved to preserve and reflect exactly the claimed runner and contact-first semantics. The compiler does not confer emergence on an encoding: the target must natively form every claimed recurrence, contact, composition, and output witness. |
| Native execution step | One declared program-state transition or continuation in a proved operational semantics. It is not minimal contact-distance. | Certified program minimum | A program proved smallest relative to one frozen source language, target, input domain, operational equivalence, and size or execution-cost measure. “Maximally minified” is informal shorthand only at that exact scope; shortest found, fewest clauses, or shortest source text is not a certificate. |

1. Never use `loop` without naming the substrate and recurrence witness.
2. Never use `shared` when only equality or synchronization has been shown.
3. Never infer one touch from a common hub. Require irreducible jointness and
   loss of contact when either recurrence is erased.
4. Never use `emergence` for a projection, classifier, quotient, or reusable
   output unless the text explicitly qualifies a different nonfoundational
   sense.

   logical knot. Use `composed logical topology` only after multiple complete
