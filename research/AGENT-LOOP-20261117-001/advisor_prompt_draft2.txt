## The question

This is the first test of the owner's whole picture in one system. The pieces:
- **The fast loop** is the learned navigating agent, which attends to a violated knot, flips one of its distinctions and remembers
  its steps. It is Dr of `MEET-TRANSFER-20261117-001` (unrefereed), both seeds.
- **The slow loop** reshapes the knot pattern under the agent. It is EARN-BUDGET's eager batched proof-based loop:
  - after each epoch of n′ flips it spends 3 times the epoch's charged fast work on tie probes (bounded refutations by
    propagation);
  - it rebuilds the pattern on the proven ties when they reach 0.3% of the classes.
- **Memory across a change.** At each rebuild the agent's whole state (values, recurrent state, ages, visit counts) is carried
  across the change by SIGNED-NAV's carry rule, or restarted from the mapped values with fresh memory.

**The primary question is the mechanism, read in flips and in charged work separately:**
1. **M1.** Does carried memory beat restarting?
2. **M2.** Does the agent with the slow loop beat the agent alone?
3. **M3.** Does the agent beat Novelty+ under the same slow loop, at the same proof effort per flip?

Beside them, the slow loop alone (SL) shows whether a fast loop is needed at all.

**Stated up front:**
- The agent costs 4 to 14 times Novelty+'s CPU per flip (SPEC-MERGE's context arm), so a win in charged time over Novelty+ under
  the same loop is unlikely. CPU is reported, and no verdict rests on it except the context line P9.
- These moves keep the allowed states: every merge is a proved tie. The carry is a mapping of the agent's memory through the
  substitution, not a statement about the knots.

The secondary question takes SPEC-MERGE's one positive signal, the co-flip evidence, as the target for proofs: probe the pairs the
search keeps moving together instead of random knots, with Novelty+ as the fast loop.

## Two problems found in calibration, and the changes

The first draft froze M1 to M3 on the local cells with EARN-BUDGET's budget rule. Calibration showed two problems.
1. **No room for memory on local patterns.** There the slow loop reduces the pattern to about 100 to 300 classes within two
   rebuilds. Only 12% to 30% of the agent's flips come after the first change, and carried and restarted memory agree to 1%.
   - **Change:** two block cells were added, where the slow loop proves little and about 90% of the flips come after the first
     change.
   - **Change:** M1 is read only where there is room (below).
2. **The budget rule favours the costlier fast loop.** The slow budget is 3 times the epoch's own fast work. The agent charges
   about 240 incidences per flip, Novelty+ about 50, so the agent buys about 5 times the proofs per flip. Under this rule the
   agent "beat" Novelty+ by about half in flips on local patterns purely through more proofs.
   - **Change:** a per-flip budget, 3 × 50 incidences per flip of the epoch, is the same for every fast loop. M3 compares the
     agent and Novelty+ under it (DrCf against GNf).

## In standard terms

A learned local-search policy with history features (a recurrent state, ages and visit counts), interleaved with inprocessing
(failed-literal probing and equivalent-literal substitution). The policy's internal state is mapped through each variable
substitution. Memory transfer under problem reformulation is not, as far as this program found, measured in the SAT literature.

**What each outcome would show.**
- **If M2 holds,** the slow loop's structure changes help a learned agent as they help Novelty+.
- **If M1 holds,** an agent's memory survives a change of structure usefully. That is the owner's metacognition picture in its
  most specific form.
- **If M3 holds,** the agent uses the reshaped pattern better than Novelty+ does, for the same proof effort.
- **None of them** would say anything about satisfiability in general. CaDiCaL solves these local patterns in about 0.05 s.

## Measures

- **Flips, charged work (v2) and CPU,** each a separate statistic: per instance the geometric mean of five runs, per cell the
  median.
- **The agent's charged work** is its engine's incidence count, reads included.
- **The slow loop's charge** counts:
  - the probes, and the sweep that finds the last unprobed knots (SL);
  - the stability counts (co-flip);
  - the rebuilds with their sorting;
  - the carry's mapping and the new handles.
- **R** is against F. Ratios between arms are paired, with 99% bootstrap intervals over instances (10,000 resamples).
- **Room** on a cell is the median share of the restarted runs' flips made after the first rebuild.

## The mechanism tests (frozen)

Each test is computed for each seed of Dr, and a claim needs **both seeds** (seed agreement).
- **A test holds on a family** when it holds on the family's first cell and on at least one of its second cells.
- **Each test is read in flips and in charged work separately.**

| Test | Ratio | Holds when |
| --- | --- | --- |
| M1, carry helps | DrC/DrR (EARN-BUDGET's rule) and DrCf/DrRf (per-flip), each separately | ≤ 0.9 with the upper end below 1; read only if the first cell has room ≥ 0.5 for both seeds, else "no room" |
| M1, carry hurts | the same | the lower end above 1 |
| M2 | DrC/Dr | ≤ 0.8 with the upper end below 0.9 |
| M3 | DrCf/GNf | ≤ 0.9 with the upper end below 1 |

## Decision rule (frozen)

Applied in order, over the two families:

1. **Every part pays in charged work:** on some family, M2 and M3 hold in charged work.
2. **Every part pays in flips only:** on some family, M2 and M3 hold in flips.
3. **The loop helps the agent, but the agent adds nothing over Novelty+ at the same proof effort:** M2 holds on some family, in
   flips or in work.
4. **No mechanism gain:** M2 holds nowhere.

Beside the rule:
- **Memory,** per family and budget: "carry helps", "carry hurts", "no difference shown" or "no room", read in flips.
- **The slow loop alone:** how often it solves on each cell.
- **The co-flip targets** pay on a cell if GNco/GN ≤ 0.9 with the upper end below 1, in work.
