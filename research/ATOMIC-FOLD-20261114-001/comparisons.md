# Additional checks on the atomic program language

These checks were specified after the primary design, while its producer was being implemented and before its official training results were available. They keep the two primary methods and their budgets intact.

1. As a reference for ordinary program synthesis, enumerate programs by number of single gates. Permit all four operations, every unordered pair of available registers including repeats, and generic output taps. Use the 32 training worlds. A lookup can read only the committed code and the downstream query. First compute the smallest possible width from the number of different training answer patterns. Find one encoder attaining that width for each context without being given the relevant input pair. Permit up to three gates. Independently execute each winner on the 32 withheld worlds. Report minimal gate counts in this grammar and accounting for deterministic search. This reference can see the labeled training panel and exploit equivalence of answer patterns. The primary policy receives a scalar score for a complete program.
2. To connect the new task to Lesson 4.7, instantiate the presented unary rules directly from the allowed states of four signed systems recovered in the earlier experiment. Fix the two outside inputs, choose one of the two candidate reads and a required output bit, then ask which values of the remaining input extend to a full allowed state. Carry the resulting six individual membership bits through the learned program. This checks the reading of those systems. Their resulting local tables fall inside the same 64-world universe and supply no independent test set.

Finding straight-line programs over a given component library is a classical synthesis problem. Combining constraints and then forgetting a variable is standard variable elimination. This experiment asks how effectively a particular reward-fitted policy finds the computation and the information its consumer needs.
