# Find a sufficient bit from two output tables

The [pair-first study](../FOLD-PAIR-PLACE-20261115-001/pair_placement.md) recovered every use of a supplied operation on single outputs. All of those programs used 24 NAND gates and a primitive-only search cost less CPU. The [earlier two-party decoder](../ANSWER-COMPOSE-20261115-001/answer_composition.md) saw the wiring. Here both outputs must be returned at once, arbitrary gates can be reused, and the solvers see only the two tables. The named solver receives the saved function `(a AND b) XOR c` up to pin permutation, as its existing six-NAND entry. Both the location and local pin order are hidden.

## What is being inferred

Fix an eligible triple of distinct raw inputs, each essential to both answers. With that triple fixed in each of its eight ways, record what **both** outputs do on every outside assignment. If there are K distinct resulting pairs of residual functions, at least K distinct messages are necessary. Otherwise two distinguishable assignments get the same message while some outside assignment requires different answers. Assigning a separate code to each class suffices. Thus the minimum number of bits at this boundary is ceil(log2 K). The target is the least such width over **all** eligible triples. Any minimizing triple is a valid answer. The verifier also requires the stated K for the actual choice. This is a multi-output instance of classical functional decomposition. [Functional decomposition and encoding](https://www.cecs.uci.edu/~papers/compendium94-03/papers/1994/dac94/pdffiles/26_1.pdf)

Each method must produce actual summary wires and a jointly executable NAND program. Every route from the chosen raw variables to the two output terminals must pass through those wires. Count summary wires and physical gates shared by the consumers. Sharing a gate, choosing a common expression, predicting a width, and certifying the smallest width are separately observable. A primitive solver may compute the same function as the supplied library and reuse it at both outputs. [Shared-logic synthesis](https://people.eecs.berkeley.edu/~alanmi/publications/2006/dac06_rwr.pdf)

## Cases and information

Use 24 matched pairs, eight at each of 5, 7 and 9 essential inputs. In the shared condition both consumers use the same local ternary answer. The matched change gives one consumer the function with a different input on the XOR port, while retaining the other consumer and the same outside context. Independently grade every eligible triple. Require the shared cases to have a one-bit interface and the changed cases to have a global minimum of two bits. At least one eligible triple must achieve two bits and every eligible triple must require at least two. Some other triples can require three. Include two additional pairs on an alternative ternary function as a separate specificity check. The candidate triple size is known by design. Different consumers can depend on common outside variables, so intersecting the two supports normally gives multiple candidate triples. Label permutations are never counted as distinct structures. With alternate minimizers, report recognition of the observable width separately from identifying the particular generator triple.

Each public record contains an opaque accounting identifier, raw input count, and two truth columns. The solver receives only the count and columns. Source expressions, group, provenance and class labels live in a separate file. The five-input AND/XOR example with 12 gates and its rewired 18-gate variant were known and checked during design. The related five-input AND/OR pair is a calibration case inside the measured panel. All panel tables and their order are bound before timing. No method can read the evaluation key.

## Decision fixed before timing

Use ten counterbalanced warm repeats and five cold repeats for the 48 primary tasks, plus two separate warm repeats of the four sensitivity tasks. Limit each method stream to one CPU worker, with a fresh worker process for each stream. Bind the same Linux CPU for every worker when available. Use median warm process CPU through the return of all 48 verified programs as the primary cost. Compute paired CPU wins, wall time, CPU after code/entry loading, common-checker CPU, physical program size and the cold sensitivity. Control for process contention by counting process CPU and retaining every wall-time repeat. The no-library benchmark is the lowest whole-stream median CPU among the three declared primitive strategies. Never splice per-rule timings with incompatible caches.

Answer any measured saving or loss directly. A smaller numerical advantage is reported at its measured size. The four operation-change cases test specificity and do not choose the winner.
