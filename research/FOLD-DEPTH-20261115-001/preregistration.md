# Supplied fold at three depths

On November 15, 2026, we chose to test where a previously learned operation belongs in a composed Boolean program. The earlier decoder computed the missing answer as (p AND q) XOR r using two successive binary operations. Its seven-NAND implementation reduced the message from four answers to three on all 24 dependent layouts. One operation alone required four bits. A later rule learner allowed one complete copy of this program. Here a submitted program can use the same saved operation at any number of subproblems. [Original two-operation decoder](../ANSWER-COMPOSE-20261115-001/answer_composition.md) · [Single-use transfer](../FOLD-REUSE-20261115-001/fold_reuse.md)

## Tasks and search

At depths two, three and four, use nested three-input operations with a total of five, seven and nine essential raw inputs. Vary which operand takes the previous result, rename input variables, and write semantically identical operations in different primitive source forms. Matched negative tasks change the local function while preserving shape and arity. Record which complete repeated expressions the negative controls exclude, any surviving local uses, the source operation counts, and the output balance. Use a small secondary panel with all nine inputs essential at each depth by expanding some leaves with disjoint primitive operations. Never count a depth-four alias as a new independent task.

The solver's complete input is the number of inputs and the truth table of the desired rule. Providing the table makes the cost of finding and constructing a program measurable at exact correctness. This also removes the source spelling, so performance on an equivalent spelling cannot establish that the solver learned a syntactic rewrite. A fresh label/sample learner is a different experiment. The search receives no target syntax, constituent boundaries, or hint about the slot in which a fold might belong.

The primitive solver may split a function over disjoint input groups and cache subproblems, including rejected decompositions. The named solver adds the unlocated reusable operation. It may first search for a valid outer XOR split and then for an AND factor on either side. The fully inlined library gets identical accessible operator knowledge and can propose every same grouping, but it emits and executes the explicit primitive expansion. The named call physically executes the original seven NANDs. A conventional primitive AND followed by XOR can compile to six. Count both actual costs. The matched semantic placement schedule allows direct comparison of packing and execution. A shared benefit over primitives would still warrant a discovery test.

A second, direct method can use the fold before recovering either binary operation. For any two candidate raw variables and the unknown function on the remaining variables, it inspects the four restricted truth columns together. For instance, when the first three columns all equal h and the fourth equals its complement, the rule can be (first AND second) XOR h. Try the distinct roles of both raw variables. The primitive counterpart has the cheaper option of removing any one variable by its two restricted columns. Each route may fall back to the common general solver on a subproblem it cannot complete. This approach uses no supplied raw pair or operand slot. For this method a trial is an actually tested binary role/singleton or ternary role/pair, plus general fallback trials. Count the actual bits inspected to create its restricted columns beside this measure. Compare the two independent strategies within matched arms.

## Costs and continuation

Charge the supplied fold zero prior acquisition in this stage. In each arm count all factor and candidate tests, rejected groups and cached failures, synthesis time, emitted physical NANDs, and verifying every returned program on every assignment. Include failed runs as incurred work and report solved denominators. Use the same operating limits in all arms. Use fresh caches per target as the primary comparison and permit identical cross-task public subproblem reuse by arity in a sensitivity test. Compress the essential variable indices in increasing input order in all three arms. The cache receives no table identifying arbitrary input permutations as equivalent. Run five sequential cold timing repeats with rotated arm order and a separate warm pass. Time search, materialization and verification separately. Report work across independently spelled target rules and across recodings with their dependence explicit.

Before seeing solver results, define appreciable growing search savings as follows. Let W be the sum of new binary operator/split trials and actual ternary candidate checks after their outer XOR and inner AND screens. Every new failed binary screen counts, including early rejections. Reusing a known verdict does not create another executed trial. Record failed and successful cache lookups separately. The CPU alternative uses actual bit reads extracting factor sections as independent corroboration. Compare the total primitive and supplied-fold W at each depth on the same recurring tasks, and report the ratio as well as the absolute savings per rule. Continue to library discovery if all paid methods and cache modes solve the full panel exactly, the absolute savings per rule are greater at depth four than at depth two (show the middle depth and all proportional trends), the saving at depth four reaches 10%, and a majority of its recurring tasks save work. Also continue if actual search CPU time meets this same depth, size and majority rule and absolute savings in actual cofactor bit reads are positive at depth four and larger than at depth two. Either of the two search strategies can trigger discovery. A change solely in the number of nodes in the returned program cannot open the next stage. A roughly constant fractional saving can qualify when it saves substantially more work on the deeper tasks. This is a deliberately permissive screen for a small pilot. Report all raw values, reversals, warm results, matched breaks and any disagreement with fixed-input-count controls.

If the screen passes, acquire a library from separate training rules without the saved operation or planted boundaries; bind its entries and choices before solving reserved structures. Include solving the training rules, candidate discovery and rejection, search and all checks at deployment. Otherwise end this study after identifying where the search and verification costs went.

These are finite experiments, with no claim about broad AI research cost or complexity. Functional decomposition and learned program libraries have independent established literatures. [Mishchenko, disjoint-support decomposition of logic functions](https://people.eecs.berkeley.edu/~alanmi/publications/2001/tech01_dsd.pdf) · [Ellis et al., DreamCoder](https://dspace.mit.edu/entities/publication/86d768ab-558f-4fb1-b92e-9288de643ccb)
